- Settled at detailing (accepted by Marko, 2026-11-04, with the file):
  - **The chart is a line chart, not a bar comparison**, so `ComparisonBarChart` is not reused. A new `SavingSummaryChart` draws it in hand-made SVG, task 006's approach (no new dependency). Recharts (installed, unused) fits worse: its `ResponsiveContainer` sizes the chart by measuring the box in JavaScript (a ResizeObserver; nothing renders in jsdom without a stub, and #113 a avoids measuring), it computes its own scale and ticks where ours come from the backend (#11, #55), and it styles through props where ours are tokens in CSS. The SVG follows `ComparisonBarChart`: user units in CSS px, x positions as percentages of the plot's width so it follows the card (#94), the y labels and grid in px from the chart's `geometry.ts`, colors and fonts from tokens in CSS (#92), the SVG hidden from assistive technology and a visually hidden table (#113 b). The line and the fill sit in a nested SVG stretched over the plot (`viewBox` in day and tick units, `preserveAspectRatio="none"`), with `vector-effect: non-scaling-stroke` so the 2 px stroke and the dashes keep their size at any width (to be checked in Chromium at the build, dashes included; if the dashes stretch, the x coordinates are computed per render from the same percentages instead, still with no measuring).
  - **The curve**: smooth as drawn, a monotone cubic through each day's value (no overshoot beyond two neighbouring days, so no peak or dip is drawn that the data does not have); no point markers, no hover, no tooltips (the general rule). A lone point (the 1st of the current month, the only day so far) shows as a Primary dot the size of the line's round cap, made larger only if invisible (not designed).

  - **The y-axis covers both lines' drawn values**, as Statistics' does: the highest and the lowest of this month's days up to today and every day of the month before.
